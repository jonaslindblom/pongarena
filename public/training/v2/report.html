Finding the balance

Only the horizontal return formula changes: 5 + round(8 × |offset| / 15), replacing the v1 multiplier 10. Paddle movement, vertical aiming, serve seeds, tick rate, timeout and all model inputs/outputs stay the same. The fastest crossing becomes 26 ticks (~0.87s), previously 22 (~0.73s).

Two identical predictive attackers played the same 2,000 rallies per candidate in the confirmation set (200 seeds, five serves, both sides). Their shot planner uses each candidate's actual speed formula.

This is the best compromise among these tested caps. A delayed-controller sensitivity check also improves, but human comfort still needs actual playtesting. No human-only physics or hidden difficulty phase is added. The reproducible comparison and raw results are in training/results/balance-v2/.

How the weights were learned

Each run collects 655,360 DAgger decisions in 10 rounds. A predictive attacker labels states visited by the learner. PPO then adds 8,192,000 decisions (250 updates × 256 environments × 128 steps), facing the original three baselines, two scripts and up to five historical copies of itself.

The actor is 6 → 64 → 64 → 3 with Tanh hidden layers, 4,803 parameters and 4,672 MACs per decision. PPO uses GAE (γ=.99, λ=.95), clipping .2, four epochs, gradient clipping, decaying learning rate, entropy regularization and a small decaying imitation anchor. Rewards are +1 for scoring, −1 for conceding and +.02 per return. The separate critic, optimizer and opponent pool are excluded from ONNX.

The three local runs completed in about 120 seconds while running concurrently. Timing is machine-specific and excludes installation/final evaluation. Methods: PPO, DAgger, CleanRL implementation notes.

Reproduce and verify

Start with training/README.md. Current rules and fixtures live in training/v2/; original v1 stays frozen. Logs, all three selected checkpoint pairs, configuration, selection records and test results are retained in training/results/v2/.

Verified: 980 exact scalar match transitions and 11 boundary cases; 32,000 randomized batched transitions; 8,192 Torch/ONNX observations per actor with identical actions; 8 complete native-ONNX matches reproduce in the live TypeScript engine (13,975 frames). V2 files have distinct filenames and rule metadata, preserving the v1 weights and report.
